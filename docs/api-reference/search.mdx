## Search Documents

Find documents with similar vectors using cosine similarity.

<Tabs>
  <Tab title="HTTP">
    ```bash
    curl -X POST http://localhost:8080/api/v1/documents/search \
      -H "Content-Type: application/json" \
      -d '{
        "collection_id": "COLLECTION_ID",
        "query_vector": [0.15, 0.22, 0.31],
        "top_k": 10
      }'
    ```
  </Tab>
  <Tab title="gRPC">
    ```bash
    grpcurl -plaintext -d '{
      "collection_id": "COLLECTION_ID",
      "query_vector": [0.15, 0.22, 0.31],
      "top_k": 10
    }' localhost:6309 document.DocumentService/SearchDocuments
    ```
  </Tab>
</Tabs>

### Request Body

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `collection_id` | string (UUID) | Yes | - | Collection to search in |
| `query_vector` | array[float] | Yes | - | Query vector (must match collection dimension) |
| `top_k` | integer | No | 10 | Number of results (max 1000) |
| `metadata_filter` | object | No | - | Filter results by metadata |
| `include_vector` | boolean | No | false | Include vectors in response |
| `min_threshold` | float | No | 0 | Minimum similarity score (0.0-1.0) |

### Response

```json
{
  "results": [
    {
      "document": {
        "id": "770e8400-e29b-41d4-a716-446655440002",
        "content": "Matching document content",
        "metadata": {"category": {"value": "example"}}
      },
      "score": 0.9876
    },
    {
      "document": {
        "id": "880e8400-e29b-41d4-a716-446655440003",
        "content": "Another matching document",
        "metadata": {}
      },
      "score": 0.8543
    }
  ]
}
```

<Info>
The `score` field represents cosine similarity (1.0 = identical, 0.0 = orthogonal).
</Info>

## Search with Metadata Filters

Combine vector similarity with metadata filtering.

```bash
curl -X POST http://localhost:8080/api/v1/documents/search \
  -H "Content-Type: application/json" \
  -d '{
    "collection_id": "COLLECTION_ID",
    "query_vector": [0.15, 0.22, 0.31],
    "top_k": 5,
    "metadata_filter": {
      "category": {"value": "electronics"}
    }
  }'
```

This will:
1. Filter documents where `metadata.category.value = "electronics"`
2. Find top 5 most similar vectors among filtered documents

## Search with Threshold

Only return results above a minimum similarity score.

```bash
curl -X POST http://localhost:8080/api/v1/documents/search \
  -H "Content-Type: application/json" \
  -d '{
    "collection_id": "COLLECTION_ID",
    "query_vector": [0.15, 0.22, 0.31],
    "top_k": 20,
    "min_threshold": 0.75
  }'
```

<Note>
If fewer than `top_k` results meet the threshold, only those matching results are returned.
</Note>

## Include Vectors in Response

Get the actual vector embeddings in search results (useful for analysis).

```bash
curl -X POST http://localhost:8080/api/v1/documents/search \
  -H "Content-Type: application/json" \
  -d '{
    "collection_id": "COLLECTION_ID",
    "query_vector": [0.15, 0.22, 0.31],
    "top_k": 5,
    "include_vector": true
  }'
```

<Tip>
Set `include_vector: false` (default) for smaller response payloads and faster transfers.
</Tip>

## Full-Text Search

Search documents by content using PostgreSQL's built-in full-text search.

<Tabs>
  <Tab title="HTTP">
    ```bash
    curl -X POST http://localhost:8080/api/v1/documents/text-search \
      -H "Content-Type: application/json" \
      -d '{
        "collection_id": "COLLECTION_ID",
        "query": "database search",
        "limit": 10
      }'
    ```
  </Tab>
  <Tab title="gRPC">
    ```bash
    grpcurl -plaintext -d '{
      "collection_id": "COLLECTION_ID",
      "query": "database search",
      "limit": 10
    }' localhost:6309 document.DocumentService/FullTextSearch
    ```
  </Tab>
</Tabs>

### Request Body

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `collection_id` | string (UUID) | Yes | - | Collection to search in |
| `query` | string | Yes | - | Search text (supports multiple words) |
| `limit` | integer | No | 10 | Maximum results to return |
| `min_rank` | float | No | 0 | Minimum relevance threshold (0.0-1.0) |

### Response

```json
{
  "result": [
    {
      "document": {
        "id": "770e8400-e29b-41d4-a716-446655440002",
        "content": "PostgreSQL is a powerful database with search capabilities",
        "vector": [0.1, 0.2, 0.3],
        "metadata": {}
      },
      "score": 0.0608
    }
  ]
}
```

<Info>
The `score` field represents relevance rank from PostgreSQL's `ts_rank` function. Higher scores indicate better matches.
</Info>

## Full-Text Search with Threshold

Only return results above a minimum relevance score.

```bash
curl -X POST http://localhost:8080/api/v1/documents/text-search \
  -H "Content-Type: application/json" \
  -d '{
    "collection_id": "COLLECTION_ID",
    "query": "vector embeddings",
    "limit": 20,
    "min_rank": 0.05
  }'
```

<Note>
Full-text search uses PostgreSQL's `to_tsvector` and `plainto_tsquery` for matching. It supports stemming (e.g., "running" matches "run") and ignores common stop words.
</Note>

## Hybrid Search

Combine vector similarity and full-text search with weighted scoring. This is the most powerful search mode, allowing you to balance semantic meaning (vectors) with keyword relevance (text).

<Tabs>
  <Tab title="HTTP">
    ```bash
    curl -X POST http://localhost:8080/api/v1/documents/hybrid-search \
      -H "Content-Type: application/json" \
      -d '{
        "collection_id": "COLLECTION_ID",
        "query_vector": [0.15, 0.22, 0.31],
        "query_text": "database search",
        "top_k": 10,
        "vector_weight": 0.7,
        "text_weight": 0.3
      }'
    ```
  </Tab>
  <Tab title="gRPC">
    ```bash
    grpcurl -plaintext -d '{
      "collection_id": "COLLECTION_ID",
      "query_vector": [0.15, 0.22, 0.31],
      "query_text": "database search",
      "top_k": 10,
      "vector_weight": 0.7,
      "text_weight": 0.3
    }' localhost:6309 document.DocumentService/HybridSearch
    ```
  </Tab>
</Tabs>

### Request Body

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `collection_id` | string (UUID) | Yes | - | Collection to search in |
| `query_vector` | array[float] | No* | - | Query vector for similarity search |
| `query_text` | string | No* | - | Query text for full-text search |
| `top_k` | integer | No | 10 | Number of results (max 1000) |
| `metadata` | object | No | - | Filter results by metadata |
| `vector_weight` | float | No | 0.5 | Weight for vector score (0.0-1.0) |
| `text_weight` | float | No | 0.5 | Weight for text score (0.0-1.0) |
| `include_vector` | boolean | No | false | Include vectors in response |

<Note>
*At least one of `query_vector` or `query_text` is required. Weights are automatically normalized to sum to 1.0.
</Note>

### Response

```json
{
  "results": [
    {
      "document": {
        "id": "770e8400-e29b-41d4-a716-446655440002",
        "content": "PostgreSQL database with vector search",
        "metadata": {}
      },
      "score": 0.8234
    }
  ]
}
```

<Info>
The `score` is a weighted combination: `(text_weight * text_rank) + (vector_weight * cosine_similarity)`.
</Info>

## Hybrid Search Use Cases

| Use Case | Vector Weight | Text Weight | Why |
|----------|---------------|-------------|-----|
| Semantic search | 0.8 | 0.2 | Prioritize meaning over keywords |
| Keyword-heavy | 0.2 | 0.8 | Prioritize exact term matches |
| Balanced | 0.5 | 0.5 | Equal importance to both |
| Vector-only | 1.0 | 0.0 | Pure vector similarity |

## Best Practices

1. **Start with small top_k** - Use `top_k=10` initially, increase as needed
2. **Use metadata filters** - Pre-filter with metadata for better performance
3. **Exclude vectors** - Set `include_vector: false` to reduce response size
4. **Set thresholds wisely** - Use `min_threshold` to filter low-quality matches
5. **Use hybrid search** - Combine vector and text search for best results
6. **Tune weights** - Experiment with `vector_weight` and `text_weight` for your use case
