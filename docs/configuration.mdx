## Environment Variables

VectorSync is configured via environment variables. Create a `.env` file in the project root.

### Database Variables

VectorSync supports two ways to configure the database connection:

**Option 1: Individual components (recommended for Docker Compose)**

| Variable | Default | Description |
|----------|---------|-------------|
| `DB_HOST` | `localhost` | PostgreSQL hostname |
| `DB_PORT` | `5432` | PostgreSQL port |
| `DB_USER` | - | Database username |
| `DB_PASSWORD` | - | Database password |
| `DB_NAME` | - | Database name |

**Option 2: Full connection string (for managed databases, Heroku, etc.)**

| Variable | Description | Example |
|----------|-------------|---------|
| `DB_URL` | PostgreSQL connection string | `postgres://user:pass@host:5432/dbname?sslmode=disable` |

<Info>
If `DB_URL` is set, it takes priority and the individual variables are ignored. If `DB_URL` is not set, the connection string is built automatically from `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, and `DB_NAME`.
</Info>

### Optional Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `GRPC_PORT` | `6309` | gRPC server port |
| `HTTP_PORT` | `8080` | HTTP gateway port |
| `LOG_LEVEL` | `info` | Logging level (debug, info, warn, error) |
| `MAX_DB_CONNECTIONS` | `50` | Maximum database connections |
| `IDLE_DB_CONNECTIONS` | `25` | Idle database connections |

### Embedding Provider Variables

These are only required if you use the raw text ingestion endpoint (`POST /api/v1/documents/ingest`).

| Variable | Required For | Description |
|----------|-------------|-------------|
| `OPENAI_API_KEY` | `openai` provider | Your OpenAI API key |
| `OPENAI_API_BASE` | `openai` provider | Custom OpenAI-compatible base URL (default: `https://api.openai.com`) |
| `COHERE_API_KEY` | `cohere` provider | Your Cohere API key |
| `COHERE_API_BASE` | `cohere` provider | Custom Cohere-compatible base URL (default: `https://api.cohere.com`) |
| `OLLAMA_HOST` | `ollama` provider | Ollama server URL (default: `http://localhost:11434`) |

## Example Configuration

<Tabs>
  <Tab title="Docker Compose">
    ```bash .env
    # Database (uses Docker service name 'db' as host)
    DB_HOST=db
    DB_PORT=5432
    DB_USER=admin
    DB_PASSWORD=your_password
    DB_NAME=vectorsync

    # Server ports
    GRPC_PORT=6309
    HTTP_PORT=8080

    # Database pool
    MAX_DB_CONNECTIONS=50
    IDLE_DB_CONNECTIONS=25
    ```
  </Tab>
  <Tab title="Local Development">
    ```bash .env
    # Database (defaults to localhost:5432)
    DB_USER=admin
    DB_PASSWORD=your_password
    DB_NAME=vectorsync

    # Server ports
    GRPC_PORT=6309
    HTTP_PORT=8080
    ```
  </Tab>
  <Tab title="Managed Database">
    ```bash .env
    # Full connection string (overrides individual vars)
    DB_URL=postgres://user:pass@managed-db.example.com:5432/vectorsync?sslmode=require
    ```
  </Tab>
</Tabs>

## Database Setup

### Installing pgvector

<Tabs>
  <Tab title="Ubuntu/Debian">
    ```bash
    sudo apt install postgresql-15-pgvector
    ```
  </Tab>
  <Tab title="macOS">
    ```bash
    brew install pgvector
    ```
  </Tab>
  <Tab title="Docker">
    ```bash
    docker pull pgvector/pgvector:pg15
    ```
  </Tab>
</Tabs>

### Running Migrations

```bash
psql $DB_URL -f migrations/001_enable_pgvector.up.sql
psql $DB_URL -f migrations/002_create_collections.up.sql
psql $DB_URL -f migrations/003_create_documents.up.sql
psql $DB_URL -f migrations/004_add_distance_metric.up.sql
psql $DB_URL -f migrations/005_fix_fts_index_size.up.sql
psql $DB_URL -f migrations/006_add_collection_embedding_config.up.sql
```

## Makefile Commands

VectorSync includes a Makefile for common tasks:

```bash
# Show all commands
make help

# Build and run
make build      # Build production binary
make run        # Run the server
make dev        # Run with hot reload (requires air)

# Development
make format     # Format code
make lint       # Run linters
make test       # Run tests

# Docker
make docker-up      # Start containers
make docker-down    # Stop containers

# Database
make migrate-up     # Run migrations
make proto          # Generate protobuf code
```
