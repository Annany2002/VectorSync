## Current Release: v0.1.0-alpha

Core vector search API with storage, retrieval, and three search modes.

### Completed

<CardGroup cols={2}>
  <Card title="Collection Management" icon="check">
    Create, read, list, and delete collections with fixed vector dimensions
  </Card>
  <Card title="Document Operations" icon="check">
    Insert, get, list, delete, and upsert documents with vectors and metadata
  </Card>
  <Card title="Vector Search" icon="check">
    Cosine similarity search with top-K results and metadata filtering
  </Card>
  <Card title="Full-Text Search" icon="check">
    PostgreSQL tsvector-based keyword search with relevance ranking
  </Card>
  <Card title="Hybrid Search" icon="check">
    Weighted vector + full-text search in a single query
  </Card>
  <Card title="Batch Operations" icon="check">
    Insert and delete up to 1000 documents atomically
  </Card>
  <Card title="Performance Tuning" icon="check">
    Connection pool (50/25), async HNSW index creation, single-lock collection cache, sync.Pool for vector serialization, synchronous_commit=off for batches, statement-level triggers, optional vector exclusion (~55x payload reduction)
  </Card>
  <Card title="Dual API" icon="check">
    gRPC (6309) and HTTP/JSON (8080) via grpc-gateway
  </Card>
  <Card title="HNSW Indexing" icon="check">
    Automatic per-collection HNSW partial indexes for fast approximate nearest neighbor search
  </Card>
  <Card title="Distance Metrics" icon="check">
    Configurable per collection: cosine, euclidean, or inner_product
  </Card>
</CardGroup>

## Completed: v0.2.0 — Ingestion Pipeline

**Theme:** Turn VectorSync from a storage layer into an end-to-end retrieval service.

Clients no longer need to pre-compute embeddings. v0.2 handles the full path from raw text to searchable vectors.

### Delivered

<CardGroup cols={2}>
  <Card title="Ingest Endpoint" icon="check">
    `POST /api/v1/documents/ingest` — Accept raw text, chunk it, generate embeddings, and store the results
  </Card>
  <Card title="Chunking Engine" icon="check">
    Three strategies: fixed-size, sentence-based, and recursive-character splitting
  </Card>
  <Card title="Embedding Orchestration" icon="check">
    Call external model APIs (OpenAI, Cohere, local Ollama) to generate vectors automatically
  </Card>
  <Card title="Collection Embedding Config" icon="check">
    Configure `embedding_provider` and `embedding_model` per collection at creation time
  </Card>
  <Card title="CI Pipeline" icon="check">
    GitHub Actions workflow: lint, format, protobuf sync, unit tests with pgvector, and E2E validation
  </Card>
</CardGroup>

## v0.3.0: Production Readiness

**Theme:** Everything needed to run VectorSync in a real deployment.

### Authentication
- **API key authentication** -- Generate, rotate, and revoke keys
- **Per-key scoping** -- Restrict keys to specific collections or operations
- **Rate limiting** -- Per-key request limits with configurable windows

### Observability
- **Structured logging** with request tracing (OpenTelemetry)
- **Prometheus metrics** -- Query latency histograms, throughput counters, pool utilization, index build progress
- **Slow query detection** -- Log and flag queries exceeding configurable latency thresholds

### Multi-tenancy
- **Namespace isolation** -- Logical separation of collections per tenant
- **Tenant-level quotas** -- Storage limits, document count caps, query rate limits
- **Schema-based isolation** -- Each tenant gets its own PostgreSQL schema

### Operational APIs
- **Collection cloning** -- Duplicate a collection with or without data
- **Data export** -- Stream documents out as JSONL for backup or migration
- **Bulk re-embedding** -- Trigger re-embedding of all documents in a collection when switching models

## v0.4.0: Scale

**Theme:** Handle datasets that don't fit in a single PostgreSQL instance.

### Sharding
- **Collection-level sharding** -- Distribute large collections across multiple PostgreSQL instances
- **Scatter-gather search** -- Query all shards in parallel, merge and re-rank results
- **Shard rebalancing** -- Move data between shards without downtime

### Streaming Ingestion
- **Bidirectional gRPC streams** -- Continuous document ingestion with backpressure
- **Ordered delivery guarantees** -- Documents processed in submission order within a collection
- **Webhook notifications** -- Push events on document insert, update, delete

### Advanced Search
- **Multi-vector queries** -- Search with multiple query vectors, merge results
- **Filtered ANN** -- Apply metadata filters during index traversal, not after
- **Sparse vector support** -- Hybrid dense + sparse search for better keyword precision
